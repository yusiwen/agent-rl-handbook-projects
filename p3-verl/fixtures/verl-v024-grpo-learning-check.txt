## what was run
# Qwen/Qwen3-1.7B, GRPO (no critic), n=6 rollouts per prompt, 8 training steps, lr 1e-6,
# train batch 16 of 24 calibrated prompts, sdpa attention, enable_thinking=false in the chat
# template, response cap 384 tokens, checkpoint saved at step 8.
# The :8003 server was stopped for the run; the container capped at --memory=118g.

## caveats that belong with these numbers
# 1. Eight steps on 24 prompts, eight epochs: the policy sees each prompt about five times.  The
#    held-out number is what makes this a measurement rather than a memory test, but the held-out
#    items are the same four families with different numbers - generalization to new *instances*,
#    not to new task types.
# 2. The first two steps' rewards are negative on some prompts (-1 penalty for a reply without an
#    answer line).  Part of the early climb is format learning, which the response-length column
#    shows shrinking into a normal range.
# 3. The container was OOM-killed after step 8 in both attempts (118g cap, no traceback because the
#    main process was SIGKILLed); the checkpoint at step 8 is what the held-out number comes from.
